# 福彩3D 数据工具箱（网页版）

单文件、离线可用的网页工具。构建产物在 [`../docs/index.html`](../docs/index.html)，
启用 GitHub Pages 后可直接访问。

## 功能

| 页面 | 内容 |
|---|---|
| 概览 | 数据快照、最近 10 期、结构分布（实际占比 vs 理论值） |
| 开奖记录 | 每期开奖号 + 组态色块（组三 / 组六 / 豹子），其余两栏显示该组态的遗漏期数 |
| 走势图 | 三位数字走势（带连线）+ 和值/跨度折线（30/50/100/200 期）；另有<b>遗漏网格</b>：按百位/十位/个位/不分位，把每期每数字的遗漏值排成表，命中格子画圈并连线（与「遗漏统计」同一口径：0 = 上一期刚出过）。网格的期次旁列出当期开奖号（红色）；<b>起始期可选</b>（最近 30/50/100/200/500/1000 期，或按每 500 期列出具体期号，可一路选到最早一期），终点永远是数据最新一期；超过 1200 期自动进入压缩模式（只画命中圈和连线，不画格子里的小字） |
| 遗漏统计 | 每位每数字的出现次数 / 频率 / 平均遗漏 / 最大遗漏 / 当前遗漏；另附<b>历史统计</b>：四个口径（百位 / 十位 / 个位 / <b>不分位</b>）的近 30 期与全历史对照（出现次数 / 平均遗漏 / 最大遗漏 / 最大连出）；再加一张<b>连出统计</b>（不分位）：相邻两期重复了几个数字的实测分布 vs 理论分布 |
| 频率分布 | 数字频率多窗口对比、和值/跨度/组态分布 |
| 选号器 | 直选复式 + 组选复式 + 筛选条件（和值 0~27 / 跨度 0~9 / 遗漏 0~9999 / 大小比 / 奇偶比 / 胆码），实时计算注数 / 金额 / 覆盖概率 / 期望回收。胆码规则可选「必须全含 / 至少含一个」：三位号码最多含 3 个不同数字，选到第 4 个时自动切到「至少含一个」并说明原因。筛选输入框只收整数：越界的值不参与筛选（标红并写明范围），离开输入框时收进最近的合法值。排除已开出号码的窗口可选 不排除 / 30 / 50 / 100 / 150 / 200 期。当期清单可一键「复制 / 下载 .txt / 打印·存 PDF」，清单含期号、选号条件、注数金额期望值与全部覆盖号码（不同选号方式可分别存） |
| 策略回测 | 5 种策略的严格样本外回测，与随机基线逐项对比；另有「排除窗口对照」一键实验（5 策略 × 6 个窗口，看清排除最近 N 期已开号码的真实代价） |

**手机版 / 电脑版是两套排版**（断点 760px，跟着窗口宽度或旋转屏幕自动切换）：

| 页面 | 电脑版 | 手机版 |
|---|---|---|
| 开奖记录 | 组三 / 组六 / 豹子 三栏分开，命中那一栏是色块 | 三栏并成一栏：色块 + 一行小字「组三 3 · 豹子 2」 |
| 历史统计 | 一张 10 列总表（球号 / 当前遗漏 / 近30期 4 项 / 全历史 4 项） | 拆成两张窄表（当前+近30期 4 列、全历史 5 列），不用左右滑 |
| 遗漏网格 | 列宽 26px、行高 22px | 行高 25px、列宽 28px（字号更大，且 56+10×28=336 正好放进 390px 屏） |

手机上原本也能用，但横向滑动会让第一列（球号）滑出视野——所以窄屏一律改成"少列多行"。

**定位**：只做历史数据的统计呈现，不做任何号码预测。措辞红线见下文。

## 重新构建

```bash
# 1) 从仓库数据生成前端数据集（读取 data/all/history_official_all_features.json）
python3 tool/extract_data.py

# 2) 合并 html + css + 数据 + js 为单文件
python3 tool/build.py
```

产物默认写到 `../docs/index.html`（GitHub Pages 直接发布这个文件）。
要写到别处用 `--out`：`python3 tool/build.py --out /tmp/preview.html`。

> `tool/data.js` 由 `extract_data.py` 生成，**不纳入版本管理**。

## 数据怎么更新（重点）

**一条命令**：抓最新开奖 → 重建数据集 → 重建网页

```bash
python scripts/refresh_all.py            # 联网抓取 + 重建（约 30 秒）
python scripts/refresh_all.py --offline  # 不联网，只用现有 data/raw 重建（约 5 秒）
python scripts/refresh_all.py --report   # 顺带跑回测与 7 天报表
```

Windows 上双击 **`更新网页数据.bat`** 等同于上面第一条；`一键运行.bat` 会把
抓取、数据集、回测、报表、网页全部跑一遍。

**自动更新**：`.github/workflows/update-data.yml` 每天北京时间 23:00 在 GitHub 上
跑一次 `scripts/refresh_all.py`，有新数据就自动提交，GitHub Pages 随之重新发布。
也可以在仓库的 Actions 页面点「Run workflow」手动触发。
如果官方接口对境外 IP 不友好导致失败，Actions 会直接把这次运行标红（并给你发通知），
这时用本地那条命令更新、再 `git push` 即可。

**页面上的时效提示**：概览页会显示「本页构建于 …」；如果数据截止日比今天落后
8 天以上，页面顶部会自动出现一条黄色提示，告诉你该更新了。

## 设计约束（改动时请遵守）

1. **措辞红线**：全站禁用 `必中`、`准确率`、`专家推荐`、`稳赚`、`包中`、`中奖率`。
   `预测` 仅可出现在否定语境（如"不做任何号码预测"）或方法学描述中。
2. **不做联系方式**：页面不得出现微信号、手机号、二维码、"加群"等导流内容。
3. **单文件自包含**：不得引入任何外部 `http(s)` 资源，保证离线可用。
4. **口径可核查**：所有展示的数值都必须能由原始开奖数据复算，且说明计算方式。
5. **不做投注建议**：只呈现数据，不给"推荐号""看好谁"。

## 手机适配

- 所有表格包在 `.table-scroll` 内，窄屏下容器内横向滑动，不撑破页面
- 数字按钮一行 5 个，触控目标 ≥ 44px
- 布局在 860px 折为单列，760px 以下进一步收紧字号与内边距
